AudioTune Pro is a Windows system-audio equalizer that lives on the desktop, not in a browser tab -- write and consume it as a dense, pro-audio control surface, not a marketing UI. Every surface reads as a piece of studio gear: layered panels, purposeful color, numeric precision. Never flatten it to a single uniform gray.

## Content fundamentals

Refer to the product as "AudioTune Pro"; the window subtitle names the current surface ("System-Wide Equalizer"). Labels are short, literal and technical -- "PRESET", "TONE", "LIMITER -- CLIPPING PROTECTION", "10-BAND GRAPHIC EQ" -- set in `section-label`: uppercase, letter-spaced, never sentence case. Control row labels (Bass, Treble, Preamp, Auto-gain protection, Equalizer enabled) are plain nouns or short imperatives, set in `control-label`, never questions or marketing copy. Numeric values are always set in the `mono` family (`value-lg`, `value-sm`, `freq-label`) with an explicit sign and one decimal for gain ("+9.9 dB", "+8.0"), so a column of values lines up and reads at a glance. No emoji, no exclamation points; the one permitted note of urgency is the warning banner, and it states the fact plainly ("Equalizer APO not found.") followed by the fix ("Install it once, then AudioTune Pro will control it automatically.").

## Visual foundations

**Color.** The window background is a two-stop, top-to-bottom gradient from `app-bg-top` to `app-bg-bottom` -- never a flat fill; it is what separates the chrome from the panels sitting on it. Panels (`Panel`) fill with `surface-panel`, take a 1px `border-panel` border and `elevation-panel`, so every panel reads as physically raised off the background rather than merely a different shade of it. Inputs, dropdowns and unfilled track backgrounds use `surface-raised`, one step lighter than the panel itself. `accent-teal` is the single primary color: the enabled state of a toggle, the active preset, a primary button, a focus ring, and the "safe" state of a gain control -- and nothing else. Do not use it for section labels, dividers or decoration; when a screen has no primary action or enabled state to show, no element should be teal. `accent-muted` carries every secondary or inactive control (secondary button fill, an idle slider handle) so the one teal accent per view stays legible. Gain-bearing controls (the 10 EQ faders, the output-level meter) carry a color that is a live function of their value, not a fixed style: `signal-safe` while comfortably under the limiter ceiling, `signal-warn` as the value approaches it, `signal-danger` inside the final margin before clipping -- pair the color with the numeric dB value and, on the Limiter section, with the `PeakIndicator` badge, so clipping risk is never communicated by color alone. Text is three steps: `text-primary` for headings, values and anything actionable; `text-secondary` for section labels and idle-state labels; `text-disabled` for a control that is switched off or unavailable (e.g. Bass/Treble/Preamp rows when Equalizer enabled is off).

**Teal and the "one primary" rule.** `signal-safe` is defined as an alias of `accent-teal`, so the safe state of a fader, of the level meter's lower segment and of the Safe badge renders teal: that is signal, read together with its number and badge, not decoration or a second primary. Everything else that is teal -- primary button, enabled toggle, active preset, focus ring -- stays limited to one primary action or state per panel (the warning Banner is its own panel, so its primary button may appear beside Save As). Do not add teal anywhere else.

**Contrast.** Anything the user must see to operate -- fader rails, toggle outlines, the resting border of text inputs and dropdowns (`track-guide`) -- reaches 3:1 on both `surface-panel` and `surface-raised`. Panel edges (`border-panel`, about 1.2:1) are deliberately faint decoration: a panel needs no border to be identified, and its separation comes from elevation. `text-disabled` and `accent-muted` are used only for disabled controls, which WCAG exempts from contrast minimums, so they stay this dark by design.

**Type.** Segoe UI leads the sans stack because this is a native Windows surface; Cascadia Mono leads the numeric stack for the same reason. Use `wordmark` once, for "AudioTune Pro" itself; every other heading is `section-label`. Body copy in dropdowns and the preset-name field is `control-label`/`body`; anything that is a measured quantity -- a dB value, a frequency, a peak estimate -- is set in the `Display` group, never in the sans family, so numbers are visually distinct from labels even out of context.

**Spacing and shape.** Sidebar sections stack on the `space-4`/`space-5` rhythm with `space-6` edge padding; the sidebar and the main EQ panel are separated by `space-8`. Radii scale with a control's role: `radius-sm` on anything you grab and drag (fader and slider handles, toggle knobs), `radius-md` on anything you click (buttons, inputs, badges), `radius-lg` on anything that contains other controls (panels, the bordered Preset unit, the warning banner), `radius-full` only on the toggle track/knob pair and small pill badges.

**States.** A disabled control drops its label to `text-disabled` and its accent to `accent-muted`, never just a lowered opacity on the same colors -- opacity alone fails the contrast floor at this palette's darkest values. Every interactive control shows a visible `focus-ring` outline, 2px, offset from the control, for keyboard use across the sidebar, faders and buttons alike. Hover states darken or lighten a surface by one step on the surface scale (`surface-panel` → `surface-raised`) rather than introducing a new color.

## Iconography

The source mockup carries no icon set of its own -- system chrome (the title-bar minimize/maximize/close glyphs) uses plain vector strokes at `text-secondary`, brightening to `text-primary` on hover; the warning banner's leading glyph and the `PeakIndicator` badges use simple geometric glyphs (triangle, circle, check) filled with their matching signal color, never a photographic or brand icon. If AudioTune Pro adopts a real icon library later, bring its files in under `assets/Icons/` and update this section to name it; until then, treat any icon here as a placeholder shape, not a locked mark.
